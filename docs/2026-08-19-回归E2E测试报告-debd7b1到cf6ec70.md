## 5. 发现的问题与修复(均经 plan-code-reviewer 审核闭环)

### 问题 #1(8857963):Node 25 残缺 localStorage 破坏 vitest
- **现象**:Phase 2 前端基线 `vitest run` 在 `useWebSocket.test.ts` 收集阶段崩溃。
- **根因**:本机 Node v25.6.0 的原生 `localStorage` 是无方法对象(上游 bug nodejs/node#60303,vitest#8757),happy-dom 不覆盖 `globalThis.localStorage` 已存在的场景。
- **修复**:新增 `web/vitest.setup.ts` polyfill(检测 `getItem` 非 function 才接管),`vitest.config.ts` 挂 setupFiles,tsconfig include 补两个文件。**0 业务代码改动**,36 文件 242 测试全过。审核结论 APPROVE。

### 问题 #2(3fe5b57):discover BV-less entry.ID 与 download 去重键脱节(L14 修复的真实回归)
- **现象**:Phase 7 E2E 发现 preview 返回 `1SW411P7Du_p001`(无 BV 前缀),而 download-by-url 落库 `BV1SW411P7Du_p001`——同视频两路径不同键,去重失效。
- **根因**:yt-dlp `--flat-playlist` 对合集返回的 entry.id 不带 `BV` 前缀(裸 base58);L14 的 `SourceIDWithPart` 锚定 entry.ID 原样保留,custom ID 兜底语义被真实数据击穿。
- **修复**:`biliutil.SourceIDWithPart` 对不匹配 BV 正则的 videoID,从 rawURL 提取 BV 作锚(仍保留 custom-id+URL-BV 的兼容语义);`discover.go` 注释同步;`videoid_test.go` 8 case 表驱动 + `discover_test.go` 夹具改 BV-less ID 钉死。审核结论 APPROVE。
- **E2E 复验**:重建二进制后 40 条 preview 全带 BV 前缀、`exists=true` 命中既有 p001/p002/p008 场次。
