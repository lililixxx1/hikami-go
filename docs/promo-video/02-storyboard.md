# 录屏分镜脚本（10 段）

> **录制顺序**：建议按 S1→S10 顺序一次录完，每段录完立刻在 OBS 里改名标记，避免后期找不到素材。
> **录屏设置**：1920×1080，30fps，OBS「显示器捕获」或浏览器内录（避免桌面杂物）。浏览器先全屏（F11），缩放 Ctrl+0 重置到 100%。
> **录屏前必做**：在浏览器 Console 注入令牌（见 `00-overview.md` 末尾），刷新确认已进入管理界面。

---

## S1 · 痛点开场 B-roll（5s）

| 项 | 内容 |
|----|------|
| 画面 | 片头 AI 生成 B-roll（见 `05-ai-tool-guide.md` 片头 prompt），不录屏 |
| 旁白 | 「你关注的直播主播，是不是越来越多？」 |
| 字幕 | 同旁白 |
| 备注 | 这段不录屏，用可灵/即梦图生视频生成 3-5s 开场画面 |

---

## S2 · 痛点转折（13s）

| 项 | 内容 |
|----|------|
| 画面 | 继续 B-roll 或转场到软件 logo 特写 |
| 旁白 | 「但如果我告诉你——有一款开源工具…你会不会想试试？」 |
| 字幕 | 同旁白 |
| 备注 | 可在这段末尾硬切到软件界面，制造「揭晓」感 |

---

## S3 · 软件亮相（10s）

| 项 | 内容 |
|----|------|
| 画面 | 浏览器打开 `http://<你的实例地址>:6334/`，镜头从地址栏缓慢下拉，露出首页全貌（直播状态区 + 场次列表） |
| 操作 | 1. 地址栏输入地址回车<br>2. 等首页加载完（直播状态卡片 + 「灰泽满 Hazel」场次列表）<br>3. 停留 3 秒让观众看清布局 |
| 旁白 | 「这就是 Hikami-Go。一个用 Go 写的、B 站直播回顾自动生成服务…」 |
| 时长 | 10s |
| 注意 | 录前确认首页有数据（灰泽满 Hazel 应显示在直播状态区，下方有 20+ 场场次） |

---

## S4 · 主播管理页（14s）

| 项 | 内容 |
|----|------|
| 画面 | 顶部导航点「主播管理」，展示主播卡片（灰泽满 Hazel），点开抽屉看自动开关 |
| 操作 | 1. 点击顶部「主播管理」<br>2. 停留，让镜头看到「灰泽满 Hazel」卡片（含头像、UID、自动录制/转写/回顾/发布开关都是绿的）<br>3. 点「编辑」打开抽屉，滚动到「自动任务」区，让观众看到 4 个开关都开着<br>4. 不用改任何东西，关掉抽屉 |
| 旁白 | 「这是我的管理界面。我关注的主播「灰泽满 Hazel」…每场直播结束，它会自动完成四件事——录播、转写、生成回顾、发布。」 |
| 时长 | 14s |
| 注意 | 抽屉里的 cookie 文件路径、发布账号信息不要停留，快速划过或后期打码 |

---

## S5 · 录播演示（13s）

| 项 | 内容 |
|----|------|
| 画面 | 回到首页或场次列表，展示一场已录制的直播（如 `bili_1298779265_live_20260806_203544`「悠闲夜晚与种田」） |
| 操作 | 1. 点「回顾管理」tab<br>2. 找到「悠闲夜晚与种田」那行（8-6 那场，状态 published）<br>3. 鼠标悬停在状态标签上，让观众看到「已发布」<br>4. 展开 started_at → ended_at 时间，体现「3 小时完整录制」（20:35 → 23:39） |
| 旁白 | 「第一步，自动录播。主播一开播，它就开始录制音视频，连弹幕一起存下来…」 |
| 时长 | 13s |
| 备选 | 若想展示「正在录制」状态，可等下次直播（live_status 的 recording 字段），但published 场次足够说明问题 |

## S6 · 转写演示（17s）

| 项 | 内容 |
|----|------|
| 画面 | 点开一场的详情，展示 ASR 转写结果（带时间轴的文字稿） |
| 操作 | 1. 点「悠闲夜晚与种田」进入详情<br>2. 切到「转写文稿」tab（或详情页里的文字稿区）<br>3. 缓慢滚动，让观众看到带时间戳的逐句文字<br>4. 可选中一段文字，体现「可复制可检索」 |
| 旁白 | 「第二步，自动转写。它把音频送进语音识别，转成带时间轴的文字稿。为了省钱，它还会先用算法剪掉里面的长沉默…」 |
| 时长 | 17s |
| 注意 | 若转写文稿 tab 没数据（published 后可能归档），改用任意 `recap_done` 或 `asr_done` 状态的场次；实例里 `bv1oa3e6venp` 是 recap_done 可备用 |

---

## S7 · 回顾生成（20s）⭐ 核心段

| 项 | 内容 |
|----|------|
| 画面 | 展示 AI 生成的回顾文档（Markdown 渲染） |
| 操作 | 1. 同一场次，点「AI 回顾」tab<br>2. 展示渲染后的回顾：标题、分段、小标题、重点<br>3. 缓慢从上往下滚动，让观众感受「这真的是一篇可读的文章」<br>4. 可切到「源码」视图展示 Markdown 原文（体现可导出） |
| 旁白 | 「第三步，也是最关键的一步——AI 回顾生成。它把整场文字稿，交给大语言模型…有分段、有小标题、有重点高亮，读起来，就像一篇认真的直播笔记。」 |
| 时长 | 20s |
| 备注 | 这是全片最该慢、最该让观众「哇」的段落。滚动速度一定要慢，让观众能扫到文字内容 |

---

## S8 · 发布演示（13s）

| 项 | 内容 |
|----|------|
| 画面 | 展示 published 状态 + publish_target（B 站动态链接） |
| 操作 | 1. 回到场次列表<br>2. 指着「已发布」状态标签<br>3. 若 UI 有 publish_target 链接，点开跳到 B 站动态页（或在旁边开个浏览器窗口提前打开动态）<br>4. 展示动态已经躺在 B 站主页 |
| 旁白 | 「最后一步，自动发布。回顾生成好，它会自动帮你发到 B 站动态，配上封面和时间。你看，这场直播的回顾，已经躺在我的主页里了。」 |
| 时长 | 13s |
| 数据 | 实例里 8-6 那场的 publish_target: `dyn_id:1233485745262428163`，若该 B 站账号动态可见可直接展示；不可见就只展示软件内的「已发布」状态 |

## S9 · 回放也能用（17s）

| 项 | 内容 |
|----|------|
| 画面 | 切到「回顾管理 · 回放」tab，演示粘贴视频 URL |
| 操作 | 1. 点顶部「回顾管理」→ 切到「回放」子 tab<br>2. 点「发现回放」打开抽屉<br>3. 在 URL 框粘贴一个示例（如 `https://www.bilibili.com/video/BV1oa3e6venp`，这是实例里已有的 `bv1oa3e6venp`）<br>4. 点「发现」，展示列表加载出来<br>5. 不用真点执行，关掉抽屉即可 |
| 旁白 | 「不只是直播录像。你丢一个 B 站视频链接给它，或者一个收藏夹地址，它也能照样转写成回顾…」 |
| 时长 | 17s |
| 注意 | 发现过程可能要几秒，录屏时自然等待，配音盖住等待感即可 |

## 总时长核算

| 段 | 时长 | 累计 |
|----|------|------|
| S1 B-roll | 5s | 0:05 |
| S2 B-roll | 13s | 0:18 |
| S3 亮相 | 10s | 0:28 |
| S4 主播页 | 14s | 0:42 |
| S5 录播 | 13s | 0:55 |
| S6 转写 | 17s | 1:12 |
| S7 回顾 ⭐ | 20s | 1:32 |
| S8 发布 | 13s | 1:45 |
| S9 回放 | 17s | 2:02 |
| S10 收尾 | 15s | 2:17 |

**纯旁白轨道约 2 分 17 秒**，加上片头 B-roll 延长、段间转场（1s × 9）、片尾 logo 停留（5s），**成片约 3 分 00 秒 ～ 3 分 30 秒**。若自配真人声（语速略快）会再短 20 秒，正好落在 3 分钟。

> 如果想要更接近 5 分钟，可在 S5/S6/S7 之间插入「等待流水线跑」的加速镜头（录一场从 recording → asr → recap 的全过程，5 倍速回放），能自然延长 60-90 秒且信息量更高。见 `05-ai-tool-guide.md` 的「延时镜头」小节。
